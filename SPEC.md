## 1. Мета і контекст

У УСС є менторство: досвідчений учасник (ментор) супроводжує новачка (менті). Менті згодом сам стає ментором, і так утворюються «родоводи» — дерева менторів.

**Цілі сайту:**
1. Кожен учасник може знайти себе і побачити, до якого дерева менторів належить, хто його започаткував і скільки в ньому людей.
2. Можна досліджувати зв'язність спільноти: огляд усіх дерев, фільтри, розфарбування, найбільші дерева.

**Принципи:**
- **Мінімалізм.** Вигляд як у графа Obsidian: темний фон, тонкі лінії, нічого зайвого.
- **Автономність.** Нетехнічний адмін оновлює дані лише через Google-таблицю. Сервер сам підтягує зміни.
- **Легка передача.** Проєкт має без болю перейти до нового відповідального: чистий код, документація, запуск однією командою.
- **Нуль витрат.** Лише безкоштовні інструменти й сервіси.
- **Приватність.** Реальних даних немає в репозиторії, контакти з форми ніколи не потрапляють на сайт.
- **Чесність щодо даних.** Дані неповні, і сайт прямо про це каже.

## 3. Обсяг

### 3.1 Входить у версію 1
- Огляд-граф усіх дерев. Вибір дерева: дерево підсвічується, решта сіра.
- Перегляд «Мій родовід»: усе дерево від засновника вниз, усі покоління, з виділеною лінією до обраної людини. Стиль Neurotree, темна тема.
- Пошук людини. Для тих, кого немає в дереві, — «ще не в дереві» і посилання на форму.
- Картка людини: засновник дерева, ментор, менті, кількість усіх нащадків.
- Список найбільших дерев.
- Панель налаштувань як в Obsidian: фільтри, відображення, режими кольорів, експорт.
- Експорт PNG у стилі Arc (рамка телефона або вікна, градієнтний фон) з перемикачем «поточний вигляд / усе дерево».
- Експорт CSV: обране дерево, а якщо нічого не обрано — усі.
- Посилання на дерево з прев'ю (Open Graph-картинка для кожного дерева).
- Плашка про неповні дані, дата оновлення, посилання на Google Form.
- Дві мови: українська (основна) і англійська. Імена кирилицею, міста перекладаються.
- Імпорт: зараз із CSV, на етапі 6 з Google-таблиці через Google Sheets API. Помилки йдуть у звіт.
- Публікація змін галочкою в Google-таблиці. Сервер сам підтягує дані.
- Docker Compose (запуск однією командою), розгортання на Proxmox.
- Документація для розробника, адміна і для передачі проєкту.

### 3.2 НЕ входить у версію 1 (не робити)
- Веб-адмінка, акаунти, логін.
- Інтеграція з WordPress (окремий майбутній етап).
- Обробка форми на сайті (форма — це Google Form).
- Транслітерація імен (буде пізніше за офіційною схемою).
- Розфарбування й огляд за містами (фільтр за містом при цьому лишається).
- Номер покоління в картці, шлях між двома людьми, мапа міжміських зв'язків, покриття даних по містах, кнопка «Тут помилка» на картці, повзунок часу.
- Аналітика відвідувань і будь-які сторонні скрипти чи CDN.
- Кілька менторів в однієї людини (це помилка імпорту, див. 5.3).

## 5. Дані

### 5.1 Поточні вхідні дані (етапи 1–5)

Файли лежать у `data/private/`, яку git ігнорує. Це копія Google-таблиці, яку зібрали вручну з багатьох джерел.

| Файл | Призначення |
|---|---|
| `mentorship_clean.csv` | **Основне джерело.** Один рядок на людину |
| `mentorship_edges.csv` | Довідковий. Імпорт його НЕ використовує |
| `mentorship_review.csv` | Довідковий. Імпорт його НЕ використовує |

Колонки `mentorship_clean.csv` (UTF-8 з BOM): `id, name, surname, first_name, level, pl, region, city, join_year, mentor_id, mentor_name, mentor_raw, match_status, city_source, in_cycle, depth, mentees_count`.

**Правила відображення (CsvDataSource):**
- `id` → `memberId`; `name` → `fullName`; `city`, `region`, `level` → як є; `join_year` → `leadershipProgramYear` (колонка `pl` дублює її і ігнорується).
- Рядки з `match_status = "зовнішній вузол (немає в списку учасників)"` — це зовнішні ментори (зараз 9 рядків, id ≥ 2001). Вони **НЕ є учасниками** і не додаються. Кожен такий рядок дає issue `EXTERNAL_MENTOR_RECORD`.
- Зв'язок `mentor_id → id` приймається **лише** коли `match_status = "точний"` і ментор є учасником.
- `match_status = "немає ментора"` означає, що зв'язку немає і помилки теж немає.
- Будь-який інший `match_status` (ментор поза списком, нечіткий збіг, лише ім'я, не знайдено, сміття) означає, що зв'язок НЕ додається. Створюється issue `UNRESOLVED_MENTOR` з оригінальним статусом і текстом `mentor_raw`.
- Колонки `depth`, `mentees_count`, `in_cycle`, `city_source`, `mentor_name` ігноруються, бо все похідне обчислюємо самі.
- Регіон береться з довідника міст (5.2, вкладка «Міста»). На етапах 1–5 початковий довідник — додаток A цього ТЗ (`data/reference/cities.csv`, його можна комітити). Якщо регіон з рядка не збігається з довідником, перемагає довідник і пишеться issue `REGION_MISMATCH` (warning).

### 5.2 Цільова структура Google-таблиці (етап 6)

Одна таблиця належить власнику. Сервісний акаунт отримує права редактора, бо він пише звіт і знімає галочку. Сервер читає **лише перелічені тут вкладки і колонки** (allowlist).

**«Учасники»**

| Колонка | Обов'язкова | Опис |
|---|---|---|
| ID | так | Унікальний стабільний ідентифікатор (рядок) |
| Ім'я | так | |
| Прізвище | так | |
| Місто | ні | Має бути в «Містах» |
| Рівень | ні | Одне з 4 значень (список у таблиці) |
| Рік ПЛ | ні | 2015…поточний рік |
| Прихований | ні | Галочка. Учасник показується як «Учасник УСС» |

**«Менторство»**

| Колонка | Обов'язкова | Опис |
|---|---|---|
| ID ментора | так | |
| ID менті | так | |
| Ментор (ім'я), Менті (ім'я) | ні | Допоміжні колонки з формулами для зручності адміна. Сервер їх ігнорує |

**«Міста»**: `Місто` (укр.), `City` (англ.), `Регіон` (одне з 4).

**«Налаштування»**: `Ключ`, `Значення`, `Опис` (див. 9.1). Тут же галочка «Опублікувати зміни».

**«Звіт імпорту»**: сервер перезаписує вкладку після кожної публікації (див. 5.3).

**«Відповіді форми»**: сюди пише Google Form. Сервер **НІКОЛИ** її не читає, бо там Telegram-контакти.

Остаточну структуру власник може уточнити на етапі 6. Відображення назв вкладок і колонок у коді ПОВИННО бути в одному місці (`sheetSchema.ts`), щоб зміна назви колонки була зміною одного рядка.

### 5.3 Валідація і звіт імпорту

**Головне правило:** додаємо все, що можна. Некоректний запис не додається, а йде у звіт. Один поганий запис НЕ ПОВИНЕН блокувати публікацію решти.

**Фатальні помилки** (публікація скасовується, на сайті лишається попередній реліз, у звіт пишеться `FATAL`):
- джерело недоступне (мережа, доступ, ключ);
- немає обов'язкової вкладки або колонки;
- після валідації не лишилося жодного учасника;
- кількість учасників упала більш ніж на 50 % порівняно з попереднім релізом (захист від випадково очищеної таблиці). Поріг налаштовується.

**Типи issues:**

| Код | Рівень | Що відбувається |
|---|---|---|
| `MISSING_MEMBER_ID` | error | Рядок учасника пропущено |
| `DUPLICATE_MEMBER_ID` | error | Перший рядок лишається, наступні пропускаються |
| `MISSING_NAME` | error | Рядок учасника пропущено |
| `EXTERNAL_MENTOR_RECORD` | error | Лише для CSV. Зовнішній ментор не додається |
| `UNRESOLVED_MENTOR` | error | Лише для CSV. Зв'язок не додано, у звіті оригінальний статус і текст |
| `MENTOR_NOT_FOUND` | error | ID ментора не існує. Зв'язок не додано |
| `MENTEE_NOT_FOUND` | error | ID менті не існує. Зв'язок не додано |
| `SELF_MENTORSHIP` | error | Зв'язок не додано |
| `DUPLICATE_LINK` | warning | Однаковий зв'язок кілька разів. Лишається один |
| `MULTIPLE_MENTORS` | error | У менті кілька різних менторів. **Жоден** із його зв'язків з менторами не додано, людина йде в розбір |
| `MENTORSHIP_CYCLE` | error | Усі зв'язки циклу не додано |
| `UNKNOWN_CITY` | warning | Міста немає в довіднику. Показується як є, без перекладу і регіону |
| `REGION_MISMATCH` | warning | Перемагає довідник |
| `UNKNOWN_LEVEL` | warning | Рівень очищено |
| `INVALID_PROGRAM_YEAR` | warning | Рік очищено |
| `INVALID_SETTING` | warning | Береться значення за замовчуванням |
| `FATAL` | fatal | Див. вище |

**Формат звіту** (однаковий для CSV-файлу і вкладки): `Рівень, Код, ID учасника, Ім'я, Рядок у джерелі, Опис українською`. Зверху підсумок: час, джерело, кількість учасників, зв'язків, дерев, помилок і попереджень. Опис зрозумілий нетехнічній людині, наприклад: «Ментора "Андріана" не знайдено серед учасників — перевірте ім'я та вкажіть ID ментора».

### 5.4 Похідні дані

Обчислюються під час імпорту в `domain`:
- **Засновник дерева** — учасник без ментора, у якого є хоча б один менті. `treeId` = `memberId` засновника. Це стабільний ідентифікатор для посилань.
- **Учасник без дерева** — без ментора і без менті. `treeId = null`, на графі не показується (крім режиму «кільце», див. 9.1), у пошуку позначається «ще не в дереві».
- `descendantCount` — кількість усіх нащадків.
- `memberCount` дерева — засновник плюс усі нащадки.
- `generation` — лише для розкладки.
- **Прихований учасник** лишається у структурі дерева, але як анонімний вузол: немає імені, міста, рівня, року, `memberId` замінено на непрозорий (`hidden-<порядковий номер>`). Він не шукається і в CSV-експорті показується як «Учасник УСС». Якщо прихований учасник — засновник, дерево називається «Дерево учасника УСС».

### 5.5 Публічний контракт даних (`graph.json`)

Сервер публікує лише це. Поля перелічені явно (whitelist). Будь-яке інше поле НЕ ПОВИННО потрапити у файл, і це перевіряє тест.

```json
{
  "schemaVersion": 1,
  "publishedAt": "2026-11-04T10:00:00Z",
  "members": [
    {
      "memberId": "1",
      "fullName": "Аділь Абдураманов",
      "cityKey": "kyiv",
      "membershipLevel": "coordinator",
      "leadershipProgramYear": 2022,
      "mentorMemberId": null,
      "treeId": "1",
      "descendantCount": 20,
      "isHidden": false
    }
  ],
  "trees": [
    { "treeId": "1", "founderMemberId": "1", "memberCount": 21 }
  ],
  "cities": [
    { "cityKey": "kyiv", "names": { "uk": "Київ", "en": "Kyiv" }, "region": "center" }
  ],
  "settings": { "formUrl": "https://forms.gle/…", "colors": { } }
}
```

- `membershipLevel` ∈ `activist | functionary | coordinator | senior-coordinator | null`.
- `region` ∈ `west | center | east | south`.
- Учасники без дерева теж є у файлі, бо вони потрібні для пошуку.
- Опис контракту лежить у `docs/data-contract.md`. Зміна контракту означає `schemaVersion + 1` і запис в ADR.

### 5.6 Приватність і безпека даних
- Репозиторій **публічний**. Реальні дані НЕ ПОВИННІ потрапити в git. `data/private/`, `.env` і ключі в `.gitignore`. CI перевіряє, що в репозиторії немає CSV поза `data/demo/` і `data/reference/`, і сканує секрети (gitleaks).
- Для розробки і тестів є синтетичний демо-набір `data/demo/` з вигаданими іменами (див. етап 0).
- Вкладку «Відповіді форми» сервер не читає. Контакти ніде не зберігаються на сервері.
- Ключ сервісного акаунта лежить лише на сервері (Docker secret або файл, змонтований тільки для читання).
- Індексація пошуковиками за замовчуванням вимкнена: `noindex` і `robots.txt` (див. розділ 14, питання 3).

## 6. Архітектура

### 6.1 Загальна схема

```
 Google-таблиця ──(Sheets API, сервісний акаунт)──┐
                                                  ▼
 data/private/*.csv ──────────────────────▶ sync-service ──▶ public-data/releases/<час>/
   (етапи 1–5)                    (імпорт → валідація →        ├─ graph.json
                                   дерева → публікація)        ├─ og/tree-<id>.png
                                         │                     └─ pages/{uk,en}/tree/<id>/index.html
                                         ▼                                  │
                        звіт: CSV-файл / вкладка «Звіт імпорту»   current ──┘ (атомарне перемикання)
                                                                            ▼
                                                     web (nginx) ──▶ браузер (web-app)
```

- **Статичний фронтенд + згенеровані дані.** Сайт не має бекенду на запит: nginx віддає статичний бандл і поточний реліз даних. Це дешево, надійно і легко переноситься.
- **sync-service** — невеликий Node-процес. Він раз на N хвилин перевіряє галочку «Опублікувати зміни» і, якщо вона стоїть, будує новий реліз. Також запускається вручну командою.
- **Атомарна публікація.** Реліз пишеться в нову папку, після успіху перемикається посилання `current`. Зберігаються останні 5 релізів. Є команда відкату на попередній реліз.

### 6.2 Стек

| Частина | Вибір | Чому |
|---|---|---|
| Мова | TypeScript 5, `strict`, `noUncheckedIndexedAccess` | Одна мова на весь проєкт простіша для наступника |
| Середовище | Node.js 22 LTS, npm workspaces | Безкоштовно, стандартно |
| Фронтенд | React 19 + Vite | Найвідоміший стек, наступнику легко підхопити |
| Граф | `force-graph` (canvas + d3-force) | Фізика як в Obsidian, вбудовані zoom, pan, drag, підсвічування. PNG через canvas. Для ~1–3 тис. вузлів запасу досить. Огорнути в адаптер (6.4), щоб бібліотеку можна було замінити |
| «Мій родовід» | `d3-hierarchy` + SVG у React, `d3-zoom` | Чіткий текст, повний контроль над стилем Neurotree |
| Кольорові шкали | `d3-scale`, `d3-interpolate` | |
| Тести | Vitest (unit), Playwright (e2e) | Playwright вже стандарт, працює в CI |
| Якість | ESLint (typescript-eslint strict), Prettier | |
| Google API | `google-auth-library` + REST Sheets API v4 | Легше за повний `googleapis` |
| OG-картинки | `@resvg/resvg-js` (SVG → PNG без браузера) | Мало пам'яті, працює в Docker |
| Веб-сервер | `nginx:alpine` | ~10 МБ RAM |

Альтернатива `force-graph` — Sigma.js (WebGL). Її свідомо відкладено: вона потрібна для десятків тисяч вузлів, а в нас ~1 тис. Рішення оформити як ADR-0002.

### 6.4 Межі модулів
- `domain` не залежить ні від чого зовнішнього: ні від React, ні від Node API, ні від мережі. Увесь код з бізнес-правилами живе тут, і саме тут найщільніші тести.
- Джерела даних реалізують один інтерфейс:
  ```ts
  interface MembershipDataSource {
    readMembershipRecords(): Promise<RawMembershipRecords>;
  }
  ```
  Реалізації: `CsvMembershipDataSource`, `GoogleSheetsMembershipDataSource`. Яку використовувати, вирішує змінна `DATA_SOURCE`.
- Звіти реалізують `ImportReportWriter`: `CsvImportReportWriter`, `GoogleSheetsImportReportWriter`.
- У фронтенді граф рендериться через `GraphRenderer` (обгортка над `force-graph`). Компоненти React не викликають API бібліотеки напряму.
- Стан застосунку (обране дерево, людина, вигляд, налаштування) зберігається в одному сторі з явними діями. Окрема бібліотека стану не потрібна: вистачить `useReducer` з контекстом. Якщо вирішиш інакше, напиши ADR.

## 7. Веб-застосунок: функції

### 7.1 Розкладка
- **Десктоп:** граф на весь екран.
  - Зліва вгорі логотип УСС, назва «Дерево Менторів УСС» і під нею кнопка «Найбільші дерева».
  - Вгорі по центру пошук і перемикач «Граф | Дерево».
  - Справа вгорі мова «УКР | ENG» (як на studfreedom.org) і кнопка налаштувань.
  - Справа панель картки (360 px), коли щось обрано.
  - Знизу по центру плашка про дані і дата оновлення.
- **Мобільний (< 768 px):** пошук вгорі. Картка, налаштування і найбільші дерева відкриваються як bottom sheet. Pinch-zoom, перетягування, вибір дотиком.
- Підтримка: останні 2 версії Chrome, Firefox, Safari, Edge і iOS Safari 16+.

### 7.2 Граф (`graphView`)
- На графі учасники, які мають дерево, і зв'язки ментор → менті. Без стрілок, як в Obsidian.
- Учасники без дерева приховані. Якщо в налаштуваннях адміна `showMembersWithoutConnections = TRUE`, вони показуються кільцем довкола графа, як в Obsidian.
- Розмір вузла: базовий радіус плюс шкала від `sqrt(descendantCount)`, з обмеженням максимуму. Користувач може вимкнути це в налаштуваннях, тоді всі вузли однакові.
- Підписи імен з'являються плавно, коли масштаб більший за поріг (`labelZoomThreshold`). Для вузла під курсором і для обраного дерева поріг нижчий. Режими «Авто / Завжди / Ніколи» є в налаштуваннях.
- **Наведення:** вузол і його прямі зв'язки стають трохи яскравішими.
- **Клік по вузлу:** обирається учасник і все його дерево.
  - Усі вузли й зв'язки дерева підсвічуються: у режимі «Однотонно» жовтим `#FFD600`, в інших режимах кольорами режиму.
  - Обраний учасник отримує білий контур.
  - Решта графа тьмяніє (сірий колір і прозорість `dimmedOpacity`).
  - Камера плавно масштабується до дерева за 600 мс, з `prefers-reduced-motion` миттєво.
- **Клік по фону або Esc** скидає вибір.
- Вузли можна перетягувати, симуляція при цьому злегка «оживає».
- **Старт:** симуляцію прогріти (`warmupTicks`), щоб граф з'являвся вже розкладеним, без хаосу. Потім вписати в екран. Розкладка детермінована: при тих самих даних граф виглядає однаково.
- **Фільтри** (7.8) не видаляють вузли, а притушують ті, що не підходять, щоб не рвати дерева. Якщо водночас обрано дерево, підсвічуються вузли, які є в дереві і проходять фільтр.

### 7.3 «Мій родовід» (`lineageView`)
- Показує **усе дерево** обраної людини: від засновника вниз, усі покоління. Якщо обрано лише дерево (зі списку чи за посиланням), людина не виділяється.
- Розкладка `d3.tree()` згори вниз у стилі Neurotree (див. додаток B):
  - імена у два рядки (ім'я / прізвище) по центру;
  - лінії йдуть вертикально від батька до горизонтальної шини, потім вертикально до дітей, із заокругленими кутами;
  - відстані розраховані так, щоб підписи ніколи не перекривались (це перевіряє тест).
- **Темна тема:**
  - фон `#000`, текст білий, лінії `#5A5A5A`;
  - ланцюжок засновник → обрана людина: лінії й імена жовті `#FFD600`, обрана людина виділена жирним;
  - біля імені маленька крапка в кольорі активного режиму кольорів.
- Над деревом: «Дерево {засновник}» · «{N} учасників» (правильні форми множини через `Intl.PluralRules`).
- Pan і zoom (`d3-zoom`). На старті дерево вписане в екран. Якщо дерево ширше за екран, камера центрується на обраній людині.
- Клік по імені обирає цю людину: картка оновлюється, ланцюжок перебудовується, вигляд лишається «Дерево».
- **Перемикач «Граф | Дерево»** — сегментований контрол угорі. «Дерево» неактивне, поки нічого не обрано; підказка: «Знайдіть себе або оберіть дерево зі списку».

### 7.4 Вибір і адреса сторінки
- `/{lang}/` — огляд.
- `/{lang}/tree/{treeId}` — обране дерево.
- `?member={memberId}` — обрана людина.
- `&view=lineage` — вигляд «Дерево».
- Кнопки браузера «назад» і «вперед» працюють. Невідомий `treeId` або `memberId` дає повідомлення «Дерево не знайдено» і огляд.
- `lang` ∈ `uk | en`. Корінь `/` перенаправляє на `/uk/`.

### 7.5 Пошук
- Поле вгорі. Підказка: «Знайдіть себе за ім'ям або прізвищем». Гаряча клавіша `/`.
- **Нормалізація:**
  - регістр;
  - усі апострофи (`ʼ ' ’ \``) вважаються однаковими;
  - зайві пробіли;
  - порядок слів не важливий («Храмов Микита» = «Микита Храмов»);
  - кожне слово запиту — префікс якогось слова імені.
- До 8 результатів: ім'я, місто і «Дерево {засновник}» або «Ще не в дереві».
- Клавіатура: ↑ ↓ Enter Esc. Доступність за шаблоном ARIA combobox.
- **Вибір людини з деревом:** обирається людина і дерево, камера наводиться на них.
- **Вибір людини без дерева:** картка «Ще не в дереві» (7.6).
- **Нічого не знайдено:** «Нікого не знайдено. Можливо, ваших даних ще немає — заповніть форму, і ми додамо вас під час наступного оновлення» і кнопка «Заповнити форму».
- Прихованих учасників не знайти.

### 7.6 Картка людини
- **Ім'я** (Apercu Bold).
- Рядок «місто · рівень · рік ПЛ». Кожне поле показується відповідно до перемикачів у налаштуваннях.
- «Засновник дерева: {ім'я}» (клікабельно). Для засновника: «Започаткував(-ла) це дерево». Стать невідома, тому формулювання нейтральне.
- «Ментор: {ім'я}» (клікабельно) або «—».
- «Менті ({n}): …» — клікабельний список.
- «Усього нащадків: {n}».
- Кнопки: «Мій родовід», «Поділитися деревом», «Завантажити PNG».
- **Картка «Ще не в дереві»:** ім'я, місто тощо і текст: «Ще не в дереві. Наші дані неповні — якщо у вас був ментор або є менті, заповніть форму, і ми додамо вас під час наступного оновлення». Кнопка «Заповнити форму» (`formUrl`).
- **Прихований учасник:** «Учасник УСС» без деталей.

### 7.7 Найбільші дерева
- Кнопка під назвою відкриває список топ-N дерев (`largestTreesCount`, за замовчуванням 10): місце, засновник, кількість учасників.
- Клік обирає дерево. На мобільному список у bottom sheet.

### 7.8 Панель налаштувань (для користувача, у стилі Obsidian)
Кнопка-шестерня відкриває праву шухляду з секціями, що згортаються. На мобільному це повноекранний sheet.
- **Фільтри**
  - Регіон: чипи, можна кілька.
  - Місто: випадний список з кількома варіантами і пошуком, сортування за кількістю людей.
  - Рівень: чипи як на `/members/` («Оберіть один або кілька рівнів», «Очистити все»).
  - Рік ПЛ: чипи років і «Без року».
- **Відображення**
  - Підписи імен: Авто / Завжди / Ніколи.
  - Показувати місто / рівень / рік ПЛ (діє на картку, підказки і CSV не змінює).
  - Розмір вузла за кількістю нащадків (увімк. / вимк.).
- **Кольори** (рівно 4 режими):
  - **Однотонно** (за замовчуванням): вузли сірі, обране дерево жовте.
  - **За роком ПЛ**: від яскраво-жовтого (найновіший рік) до темно-сірого (найстаріший). Інтерполяція в просторі Lab або OKLCH, щоб перехід був рівним. Без року — порожнє кільце (лише контур).
  - **За регіоном**: 4 кольори з конфігу.
  - **За рівнем**: 4 кольори з конфігу.
  - Коли режим не «Однотонно», внизу ліворуч з'являється легенда.
- **Експорт**: «Завантажити PNG» з перемикачем «Поточний вигляд / Усе дерево» і «Завантажити CSV».
- «Скинути налаштування».
- Налаштування користувача зберігаються в `localStorage`. Доступ огорнутий у try/catch: якщо сховище недоступне, усе працює без збереження.

### 7.9 Експорт PNG (у стилі Arc)
- **Пристрій визначається автоматично.** Телефон — це `(pointer: coarse) and (max-width: 820px)`.
  - **Телефон:** 1080×1920 (формат сторіз). Вміст у рамці телефона: заокруглений корпус, чорна рамка.
  - **Ноутбук або ПК:** 1920×1080. Вміст у рамці вікна браузера: смуга з трьома крапками і адресою `mentors.studfreedom.org`.
- **Фон:** лінійний градієнт (`exportGradientStart → exportGradientEnd`, фірмові жовті).
- **Підпис унизу:** логотип УСС і «Дерево Менторів УСС · mentors.studfreedom.org» (Apercu, чорний на жовтому, з дотриманням safe-зони логотипа).
- **Перемикач вмісту:**
  - «Поточний вигляд» — рівно те, що зараз на екрані;
  - «Усе дерево» — обране дерево вписане в кадр, а якщо нічого не обрано — увесь граф.
- Працює для обох виглядів, «Граф» і «Дерево».
- **Якість:** вміст перерендерюється в окремому canvas у потрібній роздільності, без розтягування скріншота. Перед малюванням дочекатися `document.fonts.ready`.
- Ім'я файлу: `derevo-mentoriv-{treeId|all}-{РРРР-ММ-ДД}.png`.
- На мобільному, якщо доступно, використовується Web Share API з файлом, інакше файл просто завантажується.

### 7.10 Експорт CSV
- Обране дерево, а якщо нічого не обрано — усі учасники, які є в деревах. Фільтри не враховуються.
- Колонки: `Ім'я, Місто, Рівень, Рік ПЛ, Ментор` (в англійському інтерфейсі `Name, City, Level, Program year, Mentor` і перекладені міста).
- UTF-8 з BOM (щоб Excel правильно відкрив кирилицю), розділювач кома, лапки за RFC 4180.
- Приховані учасники: «Учасник УСС», решта полів порожні.
- Ім'я файлу: `derevo-mentoriv-{treeId|all}-{РРРР-ММ-ДД}.csv`.

### 7.11 Поширення і прев'ю
- «Поділитися деревом»: на мобільному Web Share API, на десктопі копіювання `https://mentors.studfreedom.org/{lang}/tree/{treeId}` у буфер з підтвердженням «Посилання скопійовано».
- Для кожного дерева і мови sync-service генерує `pages/{lang}/tree/{treeId}/index.html`. Це копія `index.html` застосунку з мета-тегами Open Graph:
  - `og:title` = «Дерево {засновник} — Дерево Менторів УСС»;
  - `og:description` = «{N} учасників»;
  - `og:image`, `og:url`, `twitter:card=summary_large_image`.

  Месенджери не виконують JavaScript, тому теги мають бути в HTML.
- OG-картинка 1200×630 для кожного дерева (`og/tree-{treeId}.png`): темний фон, силует дерева жовтими вузлами (розкладка як у «Мій родовід»), ім'я засновника, кількість учасників, назва сайту, логотип. Рендер SVG → PNG через resvg з Apercu Pro (ttf).
- Окрема OG-картинка для головної.

### 7.12 Плашка, дата, форма
- Постійна компактна плашка внизу по центру, як «Claude can make mistakes»:
  - UA: «Дані неповні й можуть містити помилки. Не знайшли себе або бачите помилку? Заповніть форму».
  - EN: «Data is incomplete and may contain errors. Can't find yourself or spotted a mistake? Fill in the form».
  - «Заповніть форму» — посилання на `formUrl`.
- Під плашкою дрібним сірим: «Дані оновлено 4 листопада 2026» (з `publishedAt`, через `Intl.DateTimeFormat` мовою інтерфейсу).

### 7.13 Мови
- `uk` (за замовчуванням) і `en`. Перемикач «УКР | ENG».
- Рядки інтерфейсу лежать у `locales/uk.ts` і `locales/en.ts` з типізованими ключами: якщо ключа бракує, це помилка компіляції.
- Перекладаються міста (з довідника), регіони і рівні. Імена лишаються кирилицею.
- Форми множини через `Intl.PluralRules` (учасник / учасники / учасників).
- `<html lang>` і мета-теги відповідають мові.
- Англійська назва сайту: «USF Mentor Tree». Назви рівнів: Activist / Functionary / Coordinator / Senior Coordinator. **Перед релізом звірити з власником** (розділ 14).

### 7.14 Стани завантаження і помилок
- Поки вантажиться `graph.json`, показується індикатор. Якщо файл не завантажився: «Не вдалося завантажити дані» і кнопка «Спробувати ще».
- Якщо в даних немає жодного дерева, показується порожній стан з плашкою і формою.

## 10. Процес оновлення даних

Для адміна цей процес описується простими словами в `docs/admin-guide.md`, зі скріншотами таблиці.

1. Людина заповнює Google Form: що додати, виправити чи сховати, плюс Telegram. Відповідь потрапляє у вкладку «Відповіді форми».
2. Адмін переглядає відповіді і за потреби пише людині в Telegram.
3. Адмін вносить зміни у «Учасники», «Менторство» чи «Міста». Щоб сховати людину, ставить галочку «Прихований».
4. Адмін ставить галочку «Опублікувати зміни» у «Налаштуваннях».
5. Протягом ~10 хвилин сервер:
   - читає таблицю;
   - перевіряє дані;
   - публікує новий реліз;
   - перезаписує «Звіт імпорту»;
   - знімає галочку;
   - записує «Останнє оновлення» і статус.
6. Адмін переглядає звіт, виправляє помилки і за потреби повторює з кроку 3.

Технічна людина може запустити те саме вручну: `docker compose exec sync npm run sync` (з прапорцем `--force`, щоб не чекати галочки). Відкат на попередній реліз: `docker compose exec sync npm run sync:rollback`.

Для переходу з CSV на таблицю: скрипт `scripts/convert-legacy-csv-to-sheet.ts` перетворює `mentorship_clean.csv` на CSV-файли вкладок «Учасники», «Менторство», «Міста» за правилами 5.1. Їх імпортують у Google-таблицю вручну. Записи з помилками в «Менторство» не потрапляють, а йдуть у звіт для ручного розбору.

## 11. Розгортання

- **Docker Compose**, два сервіси:
  - `web`: nginx:alpine. Віддає бандл застосунку, `current`-реліз, OG-сторінки і картинки. Ліміт пам'яті 128 МБ.
  - `sync`: node:22-alpine. Ліміт пам'яті 512 МБ.

  Спільний volume `public-data`. Обидва образи збираються multi-stage, у фінальних образах немає dev-залежностей.
- **Запуск однією командою:** `docker compose up -d --build`. Без `.env` стартує з демо-даними, щоб можна було одразу подивитися.
- **Healthcheck:** `web` перевіряє `GET /healthz`. `sync` пише `status.json` (час останньої успішної і останньої спроби синхронізації, кількість помилок), healthcheck читає вік останньої спроби.
- **Логи:** структурований JSON у stdout (`docker compose logs`).
- **nginx:**
  - `index.html` і `graph.json` віддаються з `Cache-Control: no-cache` і ETag; хешовані ассети — `immutable` на рік;
  - SPA-fallback на `index.html`;
  - заголовки безпеки (12.5);
  - gzip або brotli.
- **Ресурси:** очікується < 300 МБ RAM разом і < 1 ГБ диска (з образами). Межа від власника — 4 ГБ RAM і 10 ГБ диска.
- **Proxmox:** VM або LXC з Debian 12, Docker Engine і compose plugin. Покрокова інструкція в `docs/deployment.md`:
  - встановлення;
  - створення сервісного акаунта Google Cloud (безкоштовно), увімкнення Sheets API, ключ JSON;
  - надання доступу до таблиці email-у сервісного акаунта;
  - `.env`, запуск, перевірка.
- **Тест:** тимчасовий проброс порту `WEB_PORT` у роутері.
- **Домен і HTTPS** — окремий крок пізніше (розділ 14, питання 4). Конфіг nginx і `SITE_BASE_URL` мають дозволяти поставити попереду reverse proxy без змін у коді.
- **Оновлення коду:** `git pull && docker compose up -d --build`. Дані при цьому не губляться, бо релізи лежать у volume, а джерело — це таблиця.

## 14. Відкриті питання (з'ясувати з власником, не вгадувати)

1. **Логотип УСС у SVG.** Власник надасть файл (з матеріалів гайдлайну) → `assets/brand/`.
2. **Англійська назва і переклад рівнів.** Чи «USF Mentor Tree»? Чи «Activist / Functionary / Coordinator / Senior Coordinator»? Звірити з офіційними англійськими назвами в УСС.
3. **Індексація пошуковиками.** За замовчуванням `noindex`, бо на сайті імена 1000+ людей. Чи це влаштовує?
4. **Домен і HTTPS** для `mentors.studfreedom.org` без публічної IP. Варіанти: Cloudflare Tunnel (безкоштовно, потрібен DNS на Cloudflare) або перенесення на сервер із публічною IP і Caddy або Let's Encrypt. Вирішити на окремому етапі, записати ADR.
5. **Остаточна структура Google-таблиці** (етап 6). Власник уточнить, чи підходить схема з 5.2.
6. **Остаточні кольори** режимів «За регіоном» і «За рівнем». Поки дефолти з 9.1, змінюються в таблиці.

## Додаток B. Референси

- **Граф Obsidian** (скрін від власника): темний фон, сірі тонкі лінії, кольорові групи вузлів, кільце одинаків. Взірець для `graphView`.
- **Neurotree / Academic Family Tree** (скрін «Patricia Goldman-Rakic Academic Genealogy»): імена у два рядки, лінії з шиною й заокругленими кутами, щільне компонування поколінь. Взірець для `lineageView` (у нас темна тема й лише вниз від засновника).
- **Arc «Capture»**: скрін у рамці вікна на градієнтному фоні з підписом. Взірець для експорту PNG.
- **Framily Tree** (github.com/nfischer/framily-tree): дерево студентського братства на даних із Google Sheets з перемиканням розфарбування. Найближчий аналог за задачею.
- **Connected Papers**: колір вузла за роком. Взірець для режиму «За роком ПЛ».
- **studfreedom.org/members/**: чипи фільтра рівнів, перемикач мови.
